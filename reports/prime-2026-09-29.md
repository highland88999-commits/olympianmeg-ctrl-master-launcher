## What it is

Merlin's concept: "think Google Maps on steroids." Prime is a map-based
navigator for the launcher's universe — a zoomable, explorable **star
chart** where every satellite in the launcher is a destination. Drag to
pan, pinch/scroll/buttons to zoom, tap a star to open its destination
sheet, one tap on **Travel** to launch.

- **Core:** a procedural, deterministic cosmos chart (lib/prime-chart.js).
  All 130 satellites from the shared registry become nodes grouped into
  constellation clusters (ZEUS, THOTH, ARGUS, ARTEMIS, ARES, MEDUSA).
  Positions are seeded by each key's characters — the same sky for every
  user, every visit. **Works fully offline; zero external requests at
  runtime.** Canvas 2D, DPR capped at 2, debounced resize, dirty-only
  rendering (the map costs nothing at rest).
- **Declutter by design (cleanest-UI rule):** zoomed out you see 7
  constellation clusters with counts; diving in resolves individual
  satellites and their labels. Tapping a cluster opens its member list —
  no legend chrome anywhere. The map is the interface.
- **Search** in the top bar: by name or constellation; also surfaces
  Pinned and Recent destinations when empty.
- **Nav-instruction feed** (Olympus pattern, local): a single quiet
  status pill — "Opening Chess…" — max one line, auto-dismisses. No
  kombat-tower stack; the clean-UI bar killed it.
- **Destination sheet:** name, constellation · section · route, one-line
  blurb, one primary action (Travel), a pin toggle, close. Cluster sheets
  list members; tapping a member flies to it. Sheet is fixed above the
  music bar.
- **FX:** minimal — `fx.routeLaunch(route)` fanfare on Travel (central FX
  lib, best-effort), then a plain `router.push`. No other FX inside Prime.
- **Honest labels:** the page says the chart is procedural, works offline,
  and makes no live-data claims. Satellite counts are real registry data.

## Account-mapped experience

Viewport (camera), pinned favorites, and recents persist **per account**
(lib/prime-state.js), in localStorage under account-shaped keys:

- `prime:v1:account:supabase:<uid>` — signed-in via the launcher's
  Supabase session (survives reloads and re-logins),
- `prime:v1:account:callsign:<CALLSIGN>` — the hub's `nexus_user`
  callsign when no Supabase session is available,
- `prime:v1:device` — guest fallback.

The page subscribes to auth/callsign changes: switching accounts saves
under the old key and loads under the new one, so **one account's map
state never appears under another account**. Leaderboard rule is encoded
in `PRIME_SCOPING` (`personal: per-account`, `leaderboards: universal`) —
Prime ships no leaderboard; nothing leaderboard-like may be per-user-scoped.

**Limitation (queued):** state is local-first — it survives reloads and
re-logins *on this device* but does not sync across devices, because that
needs a Supabase table and the consolidated SQL is frozen. The key shape
is account-keyed precisely so it maps cleanly onto a future
`prime_state` table. See "Merlin-only / queued" below.

## Music-bar boundary rule

`--player-clear: calc(72px + env(safe-area-inset-bottom))` on the page
root (the shell's slim bar is 56px; 72px gives breathing room; the shell
exposes no height variable, so Prime defines its own). Used for: main
bottom padding (+56px extra blank space), the destination sheet's fixed
offset, the search dropdown, and the zoom stack. iOS Safari's bottom bar
is cleared via `env(safe-area-inset-bottom)`. Page scrolls when content
overflows; everything can rest above player + Safari bar.

## Tiles decision

**Shipped WITHOUT live tiles.** The existing session endpoint
(`app/api/earth/tiles/session/route.js`) mints *3D photorealistic* tile
sessions; a 2D canvas layer would need a new server route, a separate
session type, and tile budget. The procedural chart fully carries the
concept, works offline, and is faster. Queued as a follow-up: an optional
"Earth" planet node with live 2D tiles, honestly labeled "live map tiles"
vs "charted universe."
